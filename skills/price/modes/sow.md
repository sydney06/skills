# /price sow

`/price sow <feature> <action>`, one action per run. The SOW is `docs/billing/sows/SOW-<nnn>-<slug>.md`. Every action adds a History line; above History it changes only Status and Current fee. Never mark anything signed or ask for a signature. The client reads the file as written: its body and History never name the audit or estimate file, a ledger line, a proposal, an audit, legacy, a size score or the owner's hours (the report may). History: Action `Registered`, `Sent to the Client`, `Acknowledged`, `Fee raised`, `Declined`; Amount the Current fee, never a higher audited figure; reason in plain words. Plain language: no dashes or hyphenated compounds in prose.

- **register.** Refuse when the line already has a SOW no., or has neither an Estimate nor (legacy) an audited Proposed fee (recommend `/price quote`). Number: the highest `SOW-<nnn>` in `docs/billing/sows/` plus 1, `SOW-001` when there is none. Fill `templates/sow.md`: parties from `docs/billing/README.md` (missing → `to fill`, Heads up), the scope summary and Done when lines as the scope row writes them, deliverables per repo, Estimate and Ceiling from the ledger line, Status **Draft**. Payment: `payment_terms` from `terms.md` with `clause_payment`, never from memory; absent → `to fill`, Heads up. Contract name and clause numbers come from `contract_label` and the `clause_` keys; a missing one is left out. Legacy line: a Retroactive SOW with no Warranty line, the Approved amount as its Estimate when the line is Approved, else the audited Proposed fee, Ceiling `n/a (work delivered)`. Ledger: SOW no., SOW status `Draft`. → the file exists with Status Draft.
- **sent `<date> <channel>`.** Channel is WhatsApp or email, else refuse. Status and ledger SOW status `Sent`, State `SOW Sent`; legacy: SOW status only. → History line.
- **ack `<date> <channel> "<quote or path>"`.** Refuse unless it has a date, a channel (WhatsApp or email), and a short quote of the client's words or an existing screenshot or email file's path. Draft or Sent SOW → Status and ledger SOW status `Acknowledged`; not legacy, also State `SOW Acknowledged`. Legacy line: write only SOW status and the ack date in `SOW acknowledged`, and report the increment start (the 1st of the next month); already Approved → say "run `/price approve <feature> <amount>` again to start the increment from <that date>". Never edit `retainer-schedule.md`. Other lines: leave `SOW acknowledged` alone. Acknowledged SOW with a pending raise → that raise becomes Acknowledged and Current fee its amount. → History line with the evidence.
- **raise `<amount> "<reason>" <date told> <channel>`.** Refuse an amount at or below Current fee, or one missing the reason, the date told or the channel. Up to the Ceiling → Current fee = the amount. Above the Ceiling → refuse to apply it, add a History line `raise to <amount> pending the client's reply`, leave Current fee unchanged, and say the next step is `ack` with that reply. → Current fee changed, or a pending line.
- **decline.** Status and ledger SOW status `Declined`; the feature is not billable. → History line.

Report: Headline (SOW number, action, Status, Current fee); on register also the ledger line and the estimate or audit file it came from. Next: the next step (register, sent, ack), or `/develop` once Acknowledged.
